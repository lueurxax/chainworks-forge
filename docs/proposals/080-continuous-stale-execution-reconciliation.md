Its derivation, public-safety, byte cap, and redaction semantics are:\n- Derivation: HMAC-SHA-256 over the canonical tuple (recurrence_epoch, run_id, stage_id, work_item_id, stale_class, repair_action), keyed by a daemon-scoped key that is rotated only via secret_generation rotation. The HMAC output is truncated to 96 bits (24 hex characters) and prefixed with the literal string \"p080-rik-\" for a fixed total length of 33 ASCII bytes.\n- Public-safety: repair_idempotency_key is a one-way derivation that does not contain principal_id, operator_request_dedup_key, request_fingerprint, auth tokens, or any operator-supplied text. It is safe to expose on every public lane (MCP, GraphQL, run report, release receipt) without redaction.\n- Byte cap: 33 ASCII bytes (fixed by the derivation above). Any value that does not match the fixed prefix and length is rejected by schema validation at the lane boundary.\n- Redaction: repair_idempotency_key passes through the public allow-list. It is never treated as secret-like by the redaction matrix below because its closed prefix and fixed length are negative controls in the matrix. It is null whenever repair_action is none, diagnose_only, delegated_to_p037, or delegated_to_p076. Allowed signals are SIGTERM then SIGKILL, followed by verify. Before each phase, Darwin process identity is read from pid plus process_start_boottime_nanos and parent-chain metadata. Missing metadata, PID reuse, parent mismatch, partial process enumeration, unexpected group members, or helper evidence containing raw argv/env fails closed. Helper evidence records only bounded pid/start-time/signal phase facts after redaction.\n\nDeadlines and terminal readback for helper reap:\n- SIGTERM grace: 5 s. If the member is still alive after grace, escalate to SIGKILL.\n- SIGKILL verify: 2 s. After SIGKILL, re-verify (pid, process_start_boottime_nanos) is no longer present. If verification still shows the member alive after verify, escalate one further SIGKILL attempt; if still alive, fail-closed.\n- Maximum helper-reap duration per loop tick: 10 s end-to-end across all members of the lease. If not complete within 10 s, fail-closed for the remainder of the tick.\n- Terminal readback for signal verification failure: repair_action=none, hold_reason=ambiguous_owner, projection_integrity=valid, and the helper lease remains held. Next loop tick re-verifies process identity from scratch and may retry signaling only after the standard repair cooldown.\n- Fixture p080-process-control-security proves the SIGTERM grace, SIGKILL verify timeout, max-reap duration, and the terminal readback for verification failure.\n\nDarwin process identity sources and conversion rules. The daemon reads identity from libproc and sysctl per the following pinned APIs:\n- Per-pid BSD info: proc_pidinfo(pid, PROC_PIDTBSDINFO, 0, &info, sizeof(info)). Fields used: pbi_pid, pbi_ppid, pbi_start_tvsec, pbi_start_tvusec. process_start_boottime_nanos is computed as ((pbi_start_tvsec * 1_000_000_000) + (pbi_start_tvusec * 1_000)) minus the system boottime in nanoseconds (see boottime rule below) and is stored as an unsigned integer. A negative result rejects with classifier_error and projects projection_integrity=valid with hold_reason=ambiguous_owner.\n- Boottime source: sysctl({CTL_KERN, KERN_BOOTTIME}) returns a struct timeval; boottime_nanos = (tv_sec * 1_000_000_000) + (tv_usec * 1_000). Boottime is read once per loop tick and cached; a boottime change across loop ticks (clock jump or kernel boot epoch change) invalidates every lease in the current tick, advances recurrence_epoch with reason projection_rebuilt, and forces re-verification.\n- Parent chain: sysctl({CTL_KERN, KERN_PROC, KERN_PROC_PID, pid}) returns a struct kinfo_proc; kp_eproc.e_ppid is the recorded parent pid at the time of snapshot. Parent-chain verification walks at most 8 levels up using repeated KERN_PROC_PID lookups; any link that returns ESRCH or whose start time has changed rejects.\n- Enumeration: proc_listallpids(buf, bufsize) returns a snapshot of live pids. Snapshot truncation (returned size equals bufsize) is partial-enumeration failure and rejects with classifier_error; the daemon does not retry within the same tick and projects hold_reason=ambiguous_owner.\n- Permission failures: any libproc call returning EPERM or EACCES is permission-failure and rejects with classifier_error; readback projects hold_reason=ambiguous_owner. The daemon never falls back to procfs-style reads (none exist on Darwin) and never calls ps(1).\n- PID-reuse fixture: the fixture replays a recorded sequence where pid N exits, boottime is unchanged, and a new process is assigned pid N with a different process_start_boottime_nanos; verification rejects on start-time mismatch and never signals the new process.\n\nFixture p080-process-control-security covers the libproc/sysctl call sequence, partial-enumeration failure, EPERM/EACCES rejection, parent-chain truncation depth, boottime cache invalidation, and PID-reuse rejection.\n\n## Feature Flags and Rollout Controls\nP080 reconciliation is governed by an executable rollout-control contract with the following durable shape:\n\n- Default state.
