# Proposal Review Procedure

1. Read the frozen mission context, proposal revision, and declared review role before using supporting artifacts.
2. In routing mode, derive stack, surface, and risk tags from local evidence and select the smallest reviewer set that covers material risks.
3. In specialist mode, inspect only the concerns assigned to the declared role. Use the proposal and relevant local reference evidence before historical review prose.
4. Separate proposal defects from implementation or runtime evidence gaps. Do not require builds, daemon startup, UI smoke, benchmarks, fuzzing, or live-provider proof during proposal-readiness review unless the assignment explicitly requests it.
5. Report concrete evidence and actionable findings through the declared structured output contract. Do not edit implementation files or broaden the review role.

This procedure does not grant tools, filesystem access, output ownership, or permission beyond the frozen agent binding.
